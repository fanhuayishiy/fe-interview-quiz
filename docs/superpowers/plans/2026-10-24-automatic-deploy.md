# 自动部署实施计划

用户选择自动部署，已有 1Panel 手动部署。服务器地址、现有项目目录、编排名及数据卷尚待用户提供；不得猜测或直接覆盖。

流程：main 推送/手动触发 → Node 测试 → Docker 构建与容器实测 → 保存带提交号镜像包 → SSH 上传 → 核对现有容器和数据卷 → 停机备份 → 更新并健康检查 → 失败回滚原镜像。镜像通过 SSH 传输，无需服务器能访问 GHCR。源数据不会被回滚备份自动覆盖。

- [ ] 新增 GitHub Actions 工作流，固定 action 提交号，部署默认关闭，配置完成后开启仓库变量。
- [ ] 新增生产 Compose 与服务器部署脚本，禁止隐式换卷、覆盖 .env、删除数据卷，使用服务器锁和 SSH 主机公钥校验。
- [ ] 新增容器实测与失败回滚集成测试，在 CI 验证 Docker 镜像、SQLite 持久化、旧版本恢复。
- [ ] 更新部署说明和打包清单，测试与审查；拿到服务器信息后只读核对，再完成一次实际接入验证。

首次连接不需要用户在聊天里发送密码或私钥。服务器 .env 继续只在服务器保存。未取得地址及目录时可以完成代码，但无法声称自动上线已经启用。
